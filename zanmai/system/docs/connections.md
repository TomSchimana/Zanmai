# Connections

**Read this when:** something outside the space has to be reached, or a connection needs credentials.

A connection lets Zanmai reach something that is not in your space: your calendar, a wiki, a ticket system, an image service. You say what you want in your own words, and where that source is set up on this machine, the answer comes back in the conversation.

## Using one

There is nothing to type. "What is in my calendar this week", "look that up in our wiki", "generate a picture for this flyer": if the source is already set up, it is read and you get the answer. Nothing is copied into your files by that alone. When a read should become a note in your space, say so and it is filed like anything else.

If the source is not set up yet, you are told that plainly, and setting it up is offered when a job actually needs it rather than in advance. A source you already set up for another folder on this computer is reused instead of being built a second time.

One thing is worth knowing, because it looks like a fault otherwise: a source connected during a session becomes usable in the next one. You are told that instead of being told it already works.

## What a connection can do

You choose that when it is set up, in one question with two answers.

**Read only** is the everyday case. The source is read and the answer comes back in the chat.

**Read and write** lets Zanmai put something back: a page in your wiki, a ticket, an entry in a calendar. Every write is shown to you before it goes out, whatever its size, because other people see it and no undo of yours reaches them.

Continuous syncing is not part of this. A connection is used at the moment you ask, and it is not a copy of the source sitting in your space.

## Credentials

**No password, key or token is ever stored in your space.** Where a source needs one, it goes into your operating system's keychain, or into a file outside the space, and never into a note, a commit or the conversation.

Most sources need none at all, because they were already set up in the program you run Zanmai in, and that setup is your consent: Zanmai simply uses what is there rather than asking you to authorise the same thing twice.

That is also why a source only works on the machine where you set it up. Move your space to another computer and the connection is simply absent, and says so, rather than answering with something invented.

## When it is not a connection

If the answer is already in your space, no connection is involved and you are pointed at the note instead. Reaching outside for something you already have is the mistake this avoids.
